# AI Agent Instructions - More SCP Alarm Mod

## Project Overview

**More SCP Alarm** is a large Minecraft Forge mod for version 1.20.1 that brings SCP Foundation universe elements into Minecraft. The mod includes 70+ blocks (alarm systems, facility structures, decorative elements), 50+ items (SCP documentation), and complex interactive systems powered by 130+ procedures.

- **Modid**: `more_scp_alarm`
- **Package**: `net.theo.scpalarm`
- **Build System**: Gradle with ForgeGradle
- **Java Version**: 17
- **Generated by**: MCreator (with hand-written extensions)

## Quick Start

```bash
# Build the mod
gradlew build

# Run the mod in-game
gradlew runClient

# Dedicated server
gradlew runServer
```

Output JAR will be in `build/libs/`. Working directory for runs is `run/`.

## Architecture & Code Organization

### Source Layout

```
src/main/java/net/theo/scpalarm/
├── MoreScpAlarmMod.java          # Main mod class - registers all components
├── block/                         # 70+ block classes (alarm panels, doors, etc.)
├── item/                          # 50+ item classes (documentation items, etc.)
├── procedures/                    # 130+ static utility classes for game logic
├── init/                          # Auto-generated registries (DO NOT EDIT)
│   ├── MoreScpAlarmModBlocks.java
│   ├── MoreScpAlarmModItems.java
│   ├── MoreScpAlarmModSounds.java
│   └── MoreScpAlarmModTabs.java
├── world/inventory/               # GUI containers and menu classes
├── world/level/block/entity/      # Block entities (tile entities)
├── client/                        # Client-side rendering and event handlers
└── command/                       # Custom commands (MsaCommand)
```

### Key Component Types

| Component | Location | Purpose |
|-----------|----------|---------|
| **Blocks** | `block/` | Physical blocks: alarms, doors, panels, decorative |
| **Items** | `item/` | Holdable items: documentation (Doc*), cosmetics |
| **Procedures** | `procedures/` | Static logic: alarm triggering, GUI logic, placement effects |
| **Sounds** | `init/MoreScpAlarmModSounds.java` | 40+ CASSIE tracks + character audio |
| **Registries** | `init/` | DeferredRegister for blocks, items, sounds, menus |
| **Elements** | `elements/*.mod.json` | Metadata synced with Java code by MCreator |

## Critical MCreator Conventions

### 1. Auto-Generated Files - Handle With Care

Files marked `REGENERATED on each build` (usually in `init/` and auto-generated blocks/items) will **lose all edits** outside of user code blocks on the next MCreator rebuild.

**Safe to edit**: Text between these delimiters:
```java
// Start of user code block
// ... your code here ...
// End of user code block
```

**DO NOT edit**: Everything outside these blocks in auto-generated files.

### 2. One-Way JSON → Java Sync

The `elements/*.mod.json` files are the source of truth. When you rebuild from MCreator:
- Java code regenerates from JSON
- Never manually edit auto-generated Java without updating the JSON first
- To add new features, edit the `.mod.json` in MCreator, then rebuild

### 3. Registries Are Auto-Generated

Files in `init/` (MoreScpAlarmModBlocks.java, etc.) are fully regenerated on build. Don't manually add registries here—use the MCreator UI or edit user code blocks only.

## Common Patterns

### Block Implementation

Blocks use nested anonymous classes for property mutations (state setters, collision shapes, etc.):

```java
// Example pattern - commonly used
public class MyBlockName extends Block {
    public MyBlockName() {
        super(BlockBehaviour.Properties.of()
            .destroyTime(3.0f)
            // ... properties
        );
    }
    
    // User code sections here
    // Start of user code block
    // Custom logic
    // End of user code block
}
```

### Procedure Execution

Procedures are static utility classes with `execute()` methods:

```java
public class MyProcedure {
    public static void execute(/* parameters */) {
        // Game logic here
    }
}
```

Called from blocks, items, and event handlers.

### Sound Events

Variable-range 3D audio for spatial effects:
```java
public static final RegistryObject<SoundEvent> CASSIE_TRACK_001 = 
    SOUNDS.register("cassie_track_001", ...);
```

## Common Pitfalls & How to Avoid Them

| Issue | Symptom | Solution |
|-------|---------|----------|
| Changes lost on rebuild | Code disappears after `gradlew build` | Only edit code inside user code blocks; regenerate with MCreator |
| String typos in registries | Block/item/sound doesn't register | Check spelling against `init/` registry files |
| Missing access transformer | Protected field access error | Ensure `accesstransformer.cfg` exists and is configured |
| Mismatched JSON/Java | Inconsistent behavior in-game | Rebuild from MCreator; never hand-edit synced files alone |
| Orphaned procedures | Unused code bloat | Check `elements/` for unused `.mod.json` files; delete and rebuild |

## File Types & Patterns

### `.mod.json` Files (Elements Directory)

Each element has a corresponding `.mod.json` file in `elements/`. Example names:
- `Alarm.mod.json` → `AlarmBlock.java`
- `Doc173.mod.json` → `Doc173Item.java`
- `CASSIE.mod.json` → Triggers `CassieCommand` or sound event

These define the metadata that MCreator uses to generate Java. To modify an element, edit the JSON in MCreator first.

### Resources

- **Models**: `src/main/resources/assets/more_scp_alarm/models/`
- **Textures**: `src/main/resources/assets/more_scp_alarm/textures/`
- **Sounds**: `src/main/resources/assets/more_scp_alarm/sounds/`
- **Language**: `src/main/resources/assets/more_scp_alarm/lang/en_us.json`

## Development Workflow

1. **For new features**: Edit element in MCreator → regenerate code
2. **For bug fixes**: Edit Java code in user code blocks → rebuild
3. **For resource changes**: Update models/textures/sounds → rebuild
4. **For testing**: Run `gradlew runClient` → test in-game

## Performance Considerations

- **130+ procedures**: Most are lightweight state updates
- **Variable-range sounds**: May impact performance if too many play simultaneously
- **70+ blocks**: Standard performance impact; consider batching similar blocks if needed
- **Render optimization**: Use ForgeHooks for culling and LOD

## Troubleshooting

**"Cannot resolve symbol" in IDE**: Run `gradlew build` or refresh Gradle to regenerate mappings.

**JAR won't load**: Check `MoreScpAlarmMod.java` modid matches `build.gradle` archivesBaseName.

**Changes not appearing**: Ensure you rebuilt with `gradlew build` and restarted the game.

**MCreator won't open**: Update MCreator or check `.mcreator` file isn't corrupted.
